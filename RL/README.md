# Battery Energy Optimization — ML PV Forecast + LLM Dispatch

Simulation and decision stack for a PV + battery + grid site, using:

- **real prices** from OPCOM PZU (15-minute, RON/MWh, known D-1),
- **national demand** from ENTSO-E as market context (the site is a merchant asset with zero local demand),
- an **ML PV forecast** (96-step delivery-day curve),
- a **small LLM dispatch agent** re-planning every 4 hours,
- reference strategies (idle, rule-based, MPC, perfect-foresight LP).

See `PLAN.md` for the full architecture, decisions and phases.

## Setup

Python 3.11+ is required. This checkout currently uses `pip`; `uv` is optional.

```powershell
cd RL
python -m venv .venv
.venv\Scripts\python.exe -m pip install --upgrade pip
.venv\Scripts\python.exe -m pip install -e ".[dev]"
.venv\Scripts\python.exe -m pytest
```

With `uv` installed:

```powershell
cd RL
uv sync
uv run pytest
```

Copy `.env.example` to `.env` and fill in the keys you have:

```
DEEPSEEK_API_KEY=...    # required only for the LLM agent (Phase 7)
# DEEPSEEK_BASE_URL=https://api.deepseek.com  # optional; set if your endpoint differs
ENTSOE_API_TOKEN=...    # reserved for a future ENTSO-E downloader
```

`configs/agent.yaml` uses `deepseek-flash[1m]` through an OpenAI-compatible endpoint.

`battery_rl.credentials` loads `RL/.env` automatically on first use. OS environment
variables take precedence over the file. `.env` is gitignored; only `.env.example` is
tracked. To see what is configured without printing any values:

```powershell
.venv\Scripts\python.exe scripts/check_env.py
.venv\Scripts\python.exe scripts/check_env.py --require DEEPSEEK_API_KEY
```

The second form exits 1 if the key is missing. Neither form prints the value.

The LLM client must resolve the key with `battery_rl.credentials.agent_api_key(agent_config)`
and must never log it, write it to an artifact, or put it in a prompt.

## Farm configuration UI (Phase 1A)

The map/form is the only supported source of the active training config.

```powershell
# terminal 1 — backend
cd backend
python -m venv .venv
.venv\Scripts\python.exe -m pip install -e . pytest
.venv\Scripts\python.exe -m uvicorn app.main:app --reload --port 8000

# terminal 2 — frontend
cd frontend
npm install
npm run dev
```

Open <http://localhost:5173/farm-config>. Endpoints:

- `GET/POST /api/farms`, `GET/PUT /api/farms/{id}`
- `GET /api/farms/active`
- `POST /api/farms/{id}/activate` — sets the active farm, exports `RL/configs/farm.yaml`
  and `farm.yaml.sha256`, and returns the path and checksum.

The first saved farm becomes active automatically. The UI shows the scaled PV/battery values
and warns when battery power is under 1% of national peak load (a market-materiality check,
not the balance demand).

## Configuration

All non-secret settings live in `configs/`:

| File | Purpose |
|---|---|
| `farm.example.yaml` | Example farm (Constanța, 6 MWp PV, 10 MWh / 2 MW battery) |
| `farm.yaml` | **Generated by the Phase 1A UI**; active training/evaluation config |
| `env.yaml` | Episode, 17 signed action levels, objective weights |
| `pv_model.yaml` | PV forecast target, horizon, features |
| `agent.yaml` | LLM model, prompt version, 4-hour re-plan settings |
| `eval.yaml` | Dates, split, repeats, strategies, regimes |

`battery_rl.config` is the canonical schema. The backend mirrors it; an exported
`farm.yaml` must load through `load_farm_config` and match its checksum.

```python
from battery_rl.config import load_farm_config

farm = load_farm_config("configs/farm.yaml")
print(farm.checksum(), farm.scaled_assets())
```

## Data

